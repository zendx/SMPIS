## Implementation choices versus illustrative package

- React 19 and a modular Express API. The API base is `/api/v1` on the same origin as the UI.
- PostgreSQL schema with persistent PGlite for immediate local use; optional PostgreSQL server adapter. Source schema was corrected rather than copied verbatim.
- Opaque HttpOnly session cookies and CSRF tokens replace JWT access/refresh tokens for this same-origin web client. Revocation is immediate on logout, user suspension and password reset.
- Currency is stored in integer minor units to avoid floating-point rounding. Reductions are rounded per discount step: discount first, then scholarship on the remainder.
- `school_id` and composite foreign keys guard tenant relationships. Administrators are scoped to their own school; there is no cross-school platform console.
- Applicant numbers are nullable until enrollment. Admission and enrollment changes use transactions. Statuses are preserved rather than deleting student records.
- Some identity/contact/department fields are denormalized for Phase 1; the database is not a full implementation of every table in the supplied all-phases schema.
- Roles are seeded as predefined permission templates, with permissions read by middleware. Role assignment is editable; template customization is not exposed.
- Notification delivery has explicit pending/sent/failed state. No unconfigured external service is simulated as successful.

## Validation evidence

`tests/core.test.js` exercises setup, authentication, CSRF, role/teacher/parent/school isolation, invalid dates, admission transitions, paid enrollment, capacity rejection, conditional fee calculation, invoice idempotency, exact payments, payment replay, overpayment rejection, receipts, attendance locking, duplicate marking, alert generation, staff check-in, all export formats, MFA, public applications, notification deduplication and snapshot restore.

`tests/browser.mjs` runs a real Chrome workflow on an isolated database, including required administrator authenticator setup, then checks the rendered desktop and mobile application. Test data is never seeded into the actual school workspace.
